# DM3 Internationalization (i18n) Specification

> **Status:** Active  
> **Languages:** English (en) — default, Vietnamese (vi)  
> **Last updated:** 2026-03-29

## Overview

DM3 is a multi-tenant building management platform. All user-facing text MUST go through the i18n system — no hardcoded strings in components or API responses.

---

## Frontend (React / react-i18next)

### Stack
- `react-i18next` + `i18next` + `i18next-browser-languagedetector`
- JSON locale files (flat key structure within namespaces)

### File Structure
```
apps/console/src/
├── i18n.ts                    # i18next config + init
├── locales/
│   ├── en/
│   │   ├── common.json        # Shared: buttons, labels, status
│   │   ├── auth.json          # Login, logout, session
│   │   ├── dashboard.json     # Dashboard page
│   │   ├── secure.json        # Access Control, CCTV, Intrusion, etc.
│   │   ├── manage.json        # Identities, Visitors, Attendance, etc.
│   │   ├── operate.json       # Room Booking, Parking, Maintenance, etc.
│   │   ├── smart.json         # AI Assistant, Automation
│   │   ├── devices.json       # Device management, provisioning
│   │   ├── settings.json      # Settings page
│   │   └── system.json        # System Admin pages
│   └── vi/
│       └── (same files as en/)
```

### Naming Conventions

#### Namespace = Feature Domain
| Namespace   | Scope |
|-------------|-------|
| `common`    | Buttons, status badges, table headers, generic labels |
| `auth`      | Login, register, password, session |
| `dashboard` | Dashboard widgets, stats, charts |
| `secure`    | Access Control, CCTV, Intrusion, Intercom, AI Detection, Emergency |
| `manage`    | Identities, Visitors, Contractors, Attendance, Deliveries |
| `operate`   | Room Booking, Parking, Maintenance, Guard Tour, Keys, IoT |
| `smart`     | AI Assistant, Automation |
| `devices`   | Device list, provisioning, commands, status |
| `settings`  | User settings, preferences |
| `system`    | System Admin: companies, global devices, pending registrations |

#### Key Format
```
<section>.<element>.<variant>
```

Examples:
```json
{
  "title": "Access Control",
  "description": "Manage doors and access points",
  "doors.title": "Doors",
  "doors.table.name": "Door Name",
  "doors.table.status": "Status",
  "doors.status.online": "Online",
  "doors.status.offline": "Offline",
  "doors.actions.unlock": "Unlock",
  "doors.actions.lock": "Lock",
  "doors.empty": "No doors configured"
}
```

#### Rules
1. **Keys are always English** — `doors.status.online`, never `doors.trangThai.online`
2. **Flat within namespace** — no deep nesting beyond 3 levels
3. **Descriptive keys** — `doors.actions.unlock` not `doors.btn1`
4. **Plurals** — use `_one` / `_other` suffix: `"events_one": "{{count}} event"`, `"events_other": "{{count}} events"`
5. **Interpolation** — use `{{variable}}`: `"welcome": "Welcome, {{name}}"`
6. **No HTML in translations** — use `<Trans>` component for rich text

### Usage in Components

```tsx
// Import
import { useTranslation } from 'react-i18next';

// In component
const { t } = useTranslation('secure');  // namespace

// Simple
<h1>{t('title')}</h1>

// With interpolation
<p>{t('doors.count', { count: doors.length })}</p>

// With namespace prefix (cross-namespace)
<button>{t('common:actions.save')}</button>

// Plurals
<span>{t('events', { count: 5 })}</span>
```

### Language Switcher
- Component: `LanguageSwitcher` in `packages/ui/`
- Storage: `localStorage` key `dm3-lang`
- Detection order: localStorage → browser language → fallback (en)
- Switching: `i18n.changeLanguage('vi')` — triggers re-render

### Date & Number Formatting
- Use `Intl.DateTimeFormat` and `Intl.NumberFormat` with current locale
- Helper: `useLocaleFormat()` hook
- Do NOT use hardcoded date formats like `MM/DD/YYYY`

```tsx
const { formatDate, formatNumber } = useLocaleFormat();
// en: "Mar 29, 2026"  |  vi: "29 thg 3, 2026"
// en: "1,234"          |  vi: "1.234"
```

## Backend (Go)

### Stack
- Custom `pkg/i18n` package (lightweight, no heavy framework)
- JSON locale files
- Context-based locale passing

### File Structure
```
backend/pkg/i18n/
├── i18n.go           # Core: Load(), T(), middleware
├── locales/
│   ├── en.json       # English messages
│   └── vi.json       # Vietnamese messages
```

### Locale File Format
```json
{
  "auth.invalid_credentials": "Invalid email or password",
  "auth.token_expired": "Session expired, please log in again",
  "auth.unauthorized": "You do not have permission to access this resource",
  "device.not_found": "Device not found",
  "device.already_registered": "Device is already registered",
  "validation.required": "{{field}} is required",
  "validation.invalid_email": "Invalid email format"
}
```

### API Error Response Format
```json
{
  "error": "auth.invalid_credentials",
  "message": "Invalid email or password"
}
```
- `error`: i18n key (stable, for programmatic use)
- `message`: human-readable translated text (based on Accept-Language)

### Middleware
```go
// Extract locale from Accept-Language header
// Set in context: ctx = i18n.WithLocale(ctx, "vi")
// Fallback: "en"
func LocaleMiddleware(next http.Handler) http.Handler
```

### Usage in Handlers
```go
// Get translated message
msg := i18n.T(r.Context(), "auth.invalid_credentials")

// With interpolation
msg := i18n.T(r.Context(), "validation.required", map[string]string{"field": "Email"})

// Error response helper
i18n.ErrorResponse(w, r, http.StatusUnauthorized, "auth.invalid_credentials")
```

### Rules
1. **All API error messages go through i18n** — no `fmt.Sprintf("Invalid password")`
2. **Keys match frontend pattern** — `auth.invalid_credentials` same in both
3. **Accept-Language header** — `vi`, `en`, `en-US` all supported
4. **Default: en** — if no header or unsupported language

## Adding a New Language

1. **Frontend:** Copy `src/locales/en/` → `src/locales/<code>/`, translate all files
2. **Backend:** Copy `pkg/i18n/locales/en.json` → `pkg/i18n/locales/<code>.json`, translate
3. **Register:** Add language code to i18n config (`i18n.ts` and `pkg/i18n/i18n.go`)
4. **Switcher:** Add to `LanguageSwitcher` component options

## Adding New Strings (Developer Workflow)

1. **Identify namespace** — which feature domain?
2. **Add key to `en/*.json`** — English first (source of truth)
3. **Add key to `vi/*.json`** — Vietnamese translation
4. **Use `t('namespace:key')` in component** or `i18n.T(ctx, "key")` in Go
5. **Never hardcode text** — even "OK" or "Cancel" goes through `common.json`

### Common Mistakes to Avoid
```tsx
// ❌ WRONG — hardcoded string
<button>Save</button>

// ✅ RIGHT
<button>{t('common:actions.save')}</button>

// ❌ WRONG — concatenation for sentences
t('hello') + ' ' + name + '!'

// ✅ RIGHT — interpolation
t('common:greeting', { name })

// ❌ WRONG — logic in translations
t(isAdmin ? 'admin_welcome' : 'user_welcome')

// ✅ OK — but prefer single key with variable
t('welcome', { role: isAdmin ? t('common:roles.admin') : t('common:roles.user') })
```

## Quality Standards

### English (en)
- Professional, concise
- Title Case for headings: "Access Control"
- Sentence case for descriptions: "Manage doors and access points"
- Consistent terminology (see Glossary below)

### Vietnamese (vi)
- Professional Vietnamese, NOT Google Translate
- Use standard Vietnamese IT terminology
- Consistent with existing Duali products
